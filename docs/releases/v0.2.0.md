piDeck v0.2.0 improves agent tracking, usage reporting, and nested agent cards, with refreshed Windows and Mac installers.

## Agent tracking and commands

- Track actual lifecycle hooks, paired tool IDs, and reported background work instead of guessing activity from transcript modification times.
- Distinguish running shell commands, other tools, model work, approval waits, and background jobs. Missing signals remain unknown and manually dismissible.
- Keep Claude and Codex subagent activity separate from parent activity. Link Cursor child conversations through verified local parent/spawning-tool metadata; never infer ownership from matching names or types.
- Fix hook credential/helper upgrades and Windows PowerShell invocation for Codex and Cursor. Add Codex subagent start/stop hooks.
- Preserve sanitized events across display restarts, deduplicate delivery, and persist dismissals. Completed cards stay checked when their output is read in any provider app. Explicit dismissal and the configured inactivity expiry (24 hours by default) still apply.

## Startup restoration

- Finish replaying all queued events before publishing an agent snapshot. Remove expired observations before they can briefly appear on screen.
- Keep recent completed results checked and preserve fresh live updates received during restoration. Old working observations remain explicitly unknown until confirmed.

## Agent cards

- Nest workers inside their parent's Work drawer, with crisp small sprites, short IDs, individual activity labels, and internal scrolling.
- Reserve the same vertical space for every parent. Opening, closing, or adding workers does not shift other cards.
- Replace the speech bubble and working bounce with a rear-facing laptop, animated white dots, and occasional working blinks. The laptop is raised by one sprite pixel with its lid below the eyes. Idle and completed sprites remain still; completion badges are circular. Child completion stays in its drawer; approval alerts still work.
- Keep names, short session IDs, statuses, and known or unavailable context aligned. Dismissing a parent also hides its descendants without stopping provider work.
- Retain draggable provider groups, compact usage bars, bottom navigation, and the bottom-left Settings gear.

## Provider usage and privacy

- Use Claude Desktop engine measurements or CLI status-line output for reported context and allowances, preserving an existing status line.
- Read Codex account allowances through its documented local account-limit interface and reported context through matching token records.
- Read Cursor context and background-terminal metadata locally and without modifying its database. Personal account allowances remain explicitly unavailable.
- Remove private Claude/Cursor allowance APIs, credential-refresh code, and assumed context limits. Missing or stale measurements never imply zero usage.
- Forward tool names and identifiers for activity tracking, never commands or tool arguments. Reply snippets remain opt-in.

## Desktop and documentation

- Content-fingerprinted UI assets prevent cached scripts from hiding upgrades. Settings stays on the left, and the desktop remembers its last size, position, and expanded state.
- Windows x64 and Apple Silicon/Intel Mac installers include Python and application dependencies. The Pi service uses an isolated account and private writable data.
- The README walkthrough and repaired punctuation/dimension symbols remain included.

## Install or update

Download the Windows x64 setup executable, or choose the Apple Silicon/Intel Mac DMG and move piDeck into Applications. These are **unsigned builds**: Windows may show an unknown-publisher warning, and macOS may require an explicit Open Anyway exception.

Configuration and credentials remain outside the application bundle and survive upgrades. Close the old piDeck instance before installing/opening the update. Open the bottom-left gear and choose **Connect installed agents** to refresh copied hooks. Review new or changed Codex hooks, including `SubagentStart` and `SubagentStop`, then restart provider sessions so they load the definitions.

The source ZIP supports source and Raspberry Pi installations. `SHA256SUMS` covers the downloads; per-platform build manifests record the source commit, interpreter, architecture, dependency versions, and lock hash. Dependency audits accompany native builds. Checksums provide integrity comparison, not publisher authentication. Release automation reruns CI and installer checks against the exact tagged commit before publishing.
