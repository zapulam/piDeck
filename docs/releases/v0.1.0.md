piDeck is a desk display for Raspberry Pi, Windows, and macOS, combining Claude Code, Codex, and Cursor activity with Spotify and Slack.

## Downloads and setup

- **[Windows x64 installer](https://github.com/zapulam/piDeck/releases/download/v0.1.0/piDeck-0.1.0-windows-x64-unsigned-setup.exe):** includes Python and dependencies, a raspberry application icon, direct Start menu shortcuts, optional desktop shortcut, and optional start at login. Installs Microsoft WebView2 if missing; that prerequisite needs internet access.
- **[Mac Apple Silicon DMG](https://github.com/zapulam/piDeck/releases/download/v0.1.0/piDeck-0.1.0-macos-arm64-unsigned.dmg)** or **[Mac Intel DMG](https://github.com/zapulam/piDeck/releases/download/v0.1.0/piDeck-0.1.0-macos-x86_64-unsigned.dmg):** drag piDeck into Applications, then launch it. Startup can be enabled from Settings after installation.
- **[Source ZIP](https://github.com/zapulam/piDeck/releases/download/v0.1.0/piDeck-0.1.0-source.zip):** for source installations, Raspberry Pi setup, and archival.
- **[SHA256SUMS](https://github.com/zapulam/piDeck/releases/download/v0.1.0/SHA256SUMS):** covers the source, installers, dependency audits, and build manifests. Each native build manifest records its source commit, interpreter, architecture, dependencies, and lock hash.

**Unsigned test builds:** publisher certificates are not configured. Windows may show an unknown-publisher warning and macOS may require an explicit Open Anyway exception. These packages are not publisher-verified distributions. Signing/notarization support is available when external certificates are configured.

Open Settings using the bottom-left gear to connect installed agents, connect Spotify, open configuration, or enable startup. Configuration lives outside the application folder: `%LOCALAPPDATA%\piDeck` on Windows and `~/Library/Application Support/piDeck` on macOS. Add account settings through a private `.env` using `.env.example`; packaged apps import supported secrets into Credential Manager/Keychain and remove imported secrets from `.env`. Restart after editing settings. Upgrades preserve user configuration; Windows uninstall preserves it too. On Mac, disable startup before removing the app.

## Security and upgrade notes

- Localhost displays now authenticate. Remote connections require HTTPS, origins are validated, query-token links are rejected, and trusted proxy IPs must be configured explicitly.
- Display administrator credentials and event-only hook credentials are separate. A hook cannot read Slack snapshots, create display sessions, change settings, or control playback. Legacy display credentials rotate once on upgrade: reconnect displays and reinstall hooks using the new event-only credential.
- Browser sessions expire and use HttpOnly cookies plus a separate proof confined to the tab's origin. Cookies alone do not authenticate another localhost service. Native startup uses a short-lived, single-use bootstrap instead of exposing the administrator token in its URL; WebSockets enforce the session policy too.
- Protect private files with Unix owner permissions or Windows ACLs, store packaged secrets in the OS vault, redact credentials from logs, refuse authenticated redirects, and bound requests, sessions, clients, and frontend queues.
- Message text and full project paths require separate opt-ins. Usage collection reads local sign-ins on the agent computer without forwarding provider access tokens to the display. Spotify setup uses state-validated PKCE without a bundled client secret.
- The Pi installer creates a dedicated non-login `pideck` account automatically. Root-owned code lives in `/opt/pideck`; private writable configuration/state lives in `/var/lib/pideck`. The sandboxed service binds to loopback by default. See the [README](https://github.com/zapulam/piDeck/blob/v0.1.0/README.md) for secure migration and HTTPS setup.

Read the [security policy and threat model](https://github.com/zapulam/piDeck/blob/v0.1.0/SECURITY.md) for remaining boundaries. The app does not protect against a compromised owner account or administrator, or someone viewing the physical display.

## Agents, usage, and display

- Settings is the leftmost page, matching its bottom-left gear. Agents remains the default opening page.
- Desktop windows reopen at their last size, position, and maximized/fullscreen state. Saved positions are adjusted if a monitor is disconnected. First launch uses a landscape window.

- Drag provider headings to reorder groups, with keyboard controls and saved ordering. Same-project chats have distinct fruit sprites and short session labels; Claude/Cursor subagents identify their parent project.
- Working cards have blue outlines and gently bouncing sprites with intermittent pixel thinking bubbles. Idle sprites blink and look around randomly.
- Completed turns play a brief full-screen celebration with a random cowboy hat, graduation cap, baseball cap, or sunglasses. A checkmark remains on the session card until acknowledged or work resumes; acknowledgments survive reloads.
- Two small 24px usage bars sit beneath each provider logo in a thin right column. Each fill is one solid color moving from green through yellow toward red as usage rises. Claude/Codex show short-window then weekly usage; Cursor shows API then Included. Session context usage remains separate.
- Click AGENTS or a provider logo for detailed bars, percentages, and reset times. Live session sprites collapse into a left column; click one to return to its session. Session counts remain visible in both views and agent-page text uses the navigation's monospace font.
- Recent local sessions and available usage samples are restored at startup. Claude status-line integration preserves the original command and forwards context/allowance updates; Cursor can refresh an expired local sign-in once.
- Responsive portrait/landscape layouts, screen rotation, provider logos, a dedicated Settings page behind the bottom-left gear, and bottom navigation in both orientations.
- Spotify playback controls and progress, Slack DMs/mentions, and full-screen attention alerts. The README walkthrough shows Agents, completion, detailed usage, Spotify, and Slack using mock data and generated artwork.

## Verification

- 149 non-browser tests across Python 3.11/3.13 on Linux, Windows, and Intel macOS, plus 16 Chromium integration cases. macOS 26 tests use Intel runners to avoid ARM allocation failures.
- Native Windows, Intel Mac, and Apple Silicon bundles each pass backend, standalone hook, and authenticated native-window/WebSocket smoke tests. Mac disk images and signature structure are checked.
- Windows installer lifecycle checks cover shortcut identity, startup registration, installed native authentication, upgrade retention, and uninstall cleanup/configuration retention.
- Linux CI installs the real systemd service and checks its account isolation, private storage, scoped authentication, and secret-free logs. Physical Raspberry Pi hardware and live Spotify/Slack account integration remain untested.
- Hash-locked dependency audits, Python module/function documentation conventions, attribution, JavaScript syntax, and workflow lint run in CI. Release automation reruns checks and native builds for the exact tagged commit before publication.
